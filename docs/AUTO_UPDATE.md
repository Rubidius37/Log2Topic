# Windows 자동 업데이트

Log2Topic은 트레이가 시작된 후 잠시 뒤 GitHub의 최신 릴리스를 확인하고, 이후 6시간마다 다시 확인합니다. 트레이 메뉴에서 수동으로 업데이트를 확인할 수도 있습니다. 트레이 메뉴 상단에는 현재 설치된 버전이 표시됩니다.

업데이트를 시작하면 진행 상태가 표시되는 PowerShell 창이 열립니다. 이 창을 닫지 마세요. 다운로드, 무결성 확인, 기존 프로그램 종료 대기, 파일 설치 단계가 표시되고 설치가 끝나면 새 버전으로 다시 시작할지 묻습니다. 실패한 경우에도 창과 오류 알림에 원인이 표시되며, 상세 로그는 `scripts/.runtime/update.log`에 저장됩니다.

릴리스에는 버전이 포함된 `Log2Topic-windows-v1.0.7.zip`과 같은 파일이 포함되어 있어야 합니다. GitHub에서 SHA-256 다이제스트를 제공하면 업데이트 프로그램이 이를 검증합니다. 업데이트가 시작되면 설치할 버전이 알림에 표시되고, 애플리케이션 파일을 교체한 뒤 설치 완료 대화상자가 표시됩니다. 대화상자에서 다시 시작을 선택하면 새 버전의 트레이가 실행되며, 나중에 다시 시작하려면 설치 폴더의 `Log2Topic.exe`를 실행하면 됩니다. `Workspace`, `runtime`, `scripts/.runtime` 폴더는 유지됩니다.

새 버전은 테스트와 빌드를 거쳐 릴리즈 초안으로 준비되며, 정식 공개된 뒤 업데이트 확인에 표시됩니다. 초안 상태에서는 사용자에게 새 업데이트로 표시되지 않습니다. 이미 설치된 버전보다 높은 릴리즈가 있어야 업데이트로 인식하므로, 같은 태그의 ZIP만 교체하면 새 업데이트로 표시되지 않습니다.

프로그램 업데이트에는 `README.md`, `CHANGELOG.md`와 배포용 `docs/` 사용 문서도 포함됩니다. 따라서 설치된 문서는 새 버전의 내용으로 교체됩니다. `Workspace/Subject`와 `Workspace/Topic_Reviews`의 개인 문서는 업데이트 ZIP으로 덮어쓰지 않으며, 새 버전에서 `로컬 문서 갱신`을 실행하면 현재 일지와 규칙을 기준으로 다시 생성됩니다.

설치 완료 대화상자에서 다시 시작하지 않은 경우에도 업데이트 파일은 이미 설치된 상태입니다. 트레이 메뉴를 다시 표시하려면 설치 폴더의 `Log2Topic.exe`를 직접 실행하세요.

업데이트 프로그램이 처음 포함된 릴리스는 수동으로 설치해야 합니다. 이후 릴리스부터는 기존 설치본을 자동으로 업데이트할 수 있습니다. 업데이트 로그는 `scripts/.runtime/update.log`에 기록됩니다.
