# 문제 해결

## Source ID 저장 실패

분류표에 맞는 Heading이 없어도 Source ID를 기록하고 `Unclassified/Missing Level 1`에 보존합니다. 샘플 규칙 자체는 저장 실패의 원인이 아닙니다.

Windows의 긴 백업 경로는 확장 경로 형식으로 처리합니다. 원본의 폴더 구조와 기존 Source ID는 바꾸지 않습니다. 개별 파일명 길이 제한, 쓰기 권한, 파일 잠금까지 해제하는 기능은 아닙니다.

오류에는 `File`, `stage`, 원래 예외가 표시됩니다. 백업 단계에서는 저장 위치와 권한을, 원본 교체 단계에서는 읽기 전용 여부와 다른 프로그램의 잠금을 확인하세요. 원본 변경 감지 오류라면 편집을 마친 후 다시 실행하세요. 재구축을 반복하거나 관리자 권한으로 실행하기 전에 오류 내용을 확인하세요.

### 일지 복사·붙여넣기로 인한 Source ID 중복 (`Duplicate permanent Source ID`)

이미 분류된 일지 구간을 복사해 다른 날짜 일지나 아래 구간에 붙여넣으면 `<!-- research-notes-source-id: ... -->` 주석이 함께 복사될 수 있습니다.

- **자동 복구**: 이전 분류 기록(`scripts/organizer_metadata.json`)에 원래 구간의 위치가 남아 있으면, 분류기가 원래 구간은 기존 ID로 유지하고 **새로 붙여넣은 구간에는 자동으로 새 Source ID를 발급**합니다(수정 전 원본은 자동 백업됨).
- **수동 복구 (원본 소유 구간을 특정할 수 없는 경우)**: 오류 메시지에 중복된 두 위치(`파일:줄번호`와 `first seen at 파일:줄번호`)가 함께 표시됩니다. 새로 붙여넣은 구간의 `<!-- research-notes-source-id: ... -->` 줄만 지운 뒤 다시 실행하거나, 전체 코퍼스를 교체한 경우 트레이의 `원본 일지 교체 후 ID 재생성`(`--rebuild-source-ids`)을 실행하세요.
- **원본 무수정 모드**: 원본 일지에 주석을 전혀 기록하지 않고 읽기 전용으로만 분류하려면 `.\scripts\run_local.bat --no-persist-source-ids` (또는 `python log2topic.py update --no-persist-source-ids`)를 사용할 수 있습니다.

## 업데이트 확인 실패

- 조회 오류: `scripts/.runtime/update-check.log`
- 다운로드 및 설치 오류: `scripts/.runtime/update.log`

v1.0.5 이하에는 업데이트 응답의 첨부파일 목록 처리 오류가 있어 새 수정본을 자동으로 받지 못할 수 있습니다. v1.0.6 설치본도 업데이트 실패 시 사용자 알림 없이 트레이만 종료될 수 있으므로, 해당 설치본에서 v1.0.7로 올릴 때는 최초 한 번 수동으로 프로그램 파일을 갱신해야 합니다. 작업 전 프로그램을 종료하고 설치 폴더를 백업하세요. 개인 `Workspace`, `scripts/.env`, 동기화 상태와 캐시를 배포본으로 덮어쓰지 마세요.

업데이트 여부는 릴리즈 버전으로 판단합니다. 같은 태그의 ZIP만 교체하면 새 업데이트로 인식되지 않습니다.

## 빠른 일지 동기화

전체 동기화는 로컬 분류를 먼저 시도합니다. 분류 성공 시 원본 일지, 주제 문서, 리뷰 순으로 업로드합니다. 분류가 실패하면 모든 원본 일지만 동기화하고, 주제·리뷰 업로드와 Notion·Cloudinary 정리는 생략합니다. 이때 원본 업로드가 모두 성공해도 전체 결과는 부분 실패이며 종료 코드는 1입니다. 보고서의 `Classification`과 `Daily` 단계를 구분해서 확인하세요. 연결 설정이나 원본 파일 자체에 문제가 있으면 원본 업로드도 실패할 수 있습니다.

빠른 일지 동기화는 기본적으로 수정 시각이 가장 최근인 일지 한 개만 선택합니다. `1/1 succeeded`는 전체 일지가 업로드되었다는 의미가 아닙니다. `Skipping Notion update`는 로컬 캐시와 비교해 변경이 없어 업로드를 생략했다는 뜻이며, 원격 페이지의 현재 존재 여부까지 확인했다는 뜻은 아닙니다.

## 인라인 이미지 생략 안내

`[인라인 이미지 생략]`은 해당 `data:` 이미지를 전송하지 않고 본문 동기화를 계속했다는 뜻입니다. Cloudinary 설정, 지원 MIME·인코딩, 용량·이미지 크기 제한을 확인하세요. SVG의 스크립트·외부 참조·HTML 삽입과 미지원 요소는 허용하지 않습니다. 지원 범위와 실패 정책은 [인라인 이미지 안내](NOTION_INTEGRATION.md#인라인-data-url-이미지)를 참고하세요.

검증된 이미지라도 실제 업로드 요청이 실패하면 문서 갱신을 중단하고 이전 Notion 페이지와 마지막 성공 상태를 보존합니다. 이 경우에는 생략 성공으로 처리하지 않으며, 연결과 업로드 설정을 해결한 뒤 다시 동기화해야 합니다.
