# 문제 해결

## Source ID 저장 실패

분류표에 맞는 Heading이 없어도 Source ID를 기록하고 `Unclassified/Missing Level 1`에 보존합니다. 샘플 규칙 자체는 저장 실패의 원인이 아닙니다.

Windows의 긴 백업 경로는 확장 경로 형식으로 처리합니다. 원본의 폴더 구조와 기존 Source ID는 바꾸지 않습니다. 개별 파일명 길이 제한, 쓰기 권한, 파일 잠금까지 해제하는 기능은 아닙니다.

오류에는 `File`, `stage`, 원래 예외가 표시됩니다. 백업 단계에서는 저장 위치와 권한을, 원본 교체 단계에서는 읽기 전용 여부와 다른 프로그램의 잠금을 확인하세요. 원본 변경 감지 오류라면 편집을 마친 후 다시 실행하세요. 재구축을 반복하거나 관리자 권한으로 실행하기 전에 오류 내용을 확인하세요.

## 업데이트 확인 실패

- 조회 오류: `scripts/.runtime/update-check.log`
- 다운로드 및 설치 오류: `scripts/.runtime/update.log`

v1.0.5 이하에는 업데이트 응답의 첨부파일 목록 처리 오류가 있어 새 수정본을 자동으로 받지 못할 수 있습니다. 최초 한 번 수동으로 프로그램 파일을 갱신해야 합니다. 작업 전 프로그램을 종료하고 설치 폴더를 백업하세요. 개인 `Workspace`, `scripts/.env`, 동기화 상태와 캐시를 배포본으로 덮어쓰지 마세요.

업데이트 여부는 릴리즈 버전으로 판단합니다. 같은 태그의 ZIP만 교체하면 새 업데이트로 인식되지 않습니다.

## 빠른 일지 동기화

전체 동기화는 로컬 분류를 먼저 시도합니다. 분류 성공 시 원본 일지, 주제 문서, 리뷰 순으로 업로드합니다. 분류가 실패하면 모든 원본 일지만 동기화하고, 주제·리뷰 업로드와 Notion·Cloudinary 정리는 생략합니다. 이때 원본 업로드가 모두 성공해도 전체 결과는 부분 실패이며 종료 코드는 1입니다. 보고서의 `Classification`과 `Daily` 단계를 구분해서 확인하세요. 연결 설정이나 원본 파일 자체에 문제가 있으면 원본 업로드도 실패할 수 있습니다.

빠른 일지 동기화는 기본적으로 수정 시각이 가장 최근인 일지 한 개만 선택합니다. `1/1 succeeded`는 전체 일지가 업로드되었다는 의미가 아닙니다. `Skipping Notion update`는 로컬 캐시와 비교해 변경이 없어 업로드를 생략했다는 뜻이며, 원격 페이지의 현재 존재 여부까지 확인했다는 뜻은 아닙니다.
